## Bug 1 — Bright settings screen on device

**Root cause (confirmed):** `global.css` line 6 defines `--color-background: ;` — an **empty token**. This kills the `bg-background` utility everywhere it's used, leaving those views transparent so the (white, light-mode) native screen background shows through. Your simulator was in dark mode, so the transparent view looked dark and hid the bug; your phone is in light mode, so it's white. `UIUserInterfaceStyle=Dark` is correctly in Info.plist — it's irrelevant once the view paints nothing. Affected: `settings.tsx` (fully exposed — no fallback behind it), `countdownRing.tsx` (the card will be broken on device too now that shows load again), `(tabs)/index.tsx` (masked by the explicit `Colors.background` SafeAreaView behind it).

**Fix (2 small changes):**
1. `global.css`: set `--color-background: #121212;` (matches `Colors.background`, forced-dark app, deterministic on all devices).
2. `_layout.tsx`: add `contentStyle: { backgroundColor: Colors.dark }` to the settings `Stack.Screen` so the native screen container behind it is explicitly dark — defense in depth.

## Bug 2 — "No Show Today" in the 2–3 AM window (rebuild button included)

**Root cause (confirmed, exact timeline):** Your September config ends shows at midnight with `clearHour = endHour + 2` → **clearTime = 2:00 AM**. At 2:12 AM, `useLoadShow` correctly detected a new day and called `loadShow`, which has an after-midnight branch: `getHours() < 3` → prefer **yesterday's** show. Yesterday's show exists (non-null), so the `?? buildTodaysShow(date)` fallback never fires — but it's already **past its clearTime** (2:00 AM), so `getPhase` returns `null` → "No Show Today." Tapping Restart App calls the same `loadShow` → same branch → same wrong result. It "fixed itself hours later" because after 3:00 AM the `< 3` branch stops preferring yesterday, and today's show loads as preShow. The `??` fallback only handles "yesterday had no show," not "yesterday's show is expired."

**Fix:** in `store.ts` `loadShow`, keep yesterday's show only while it's still live — otherwise roll forward to today's show:

```ts
const yesterdayShow =
  date.getHours() < 3 ? buildTodaysShow(yesterday, config, role) : null;
const show =
  yesterdayShow && yesterdayShow.clearTime > date.getTime()
    ? yesterdayShow
    : buildTodaysShow(date, config, role);
```

Behavior after fix: 0:00–2:00 AM → yesterday's show (postShow, as before); 2:00–3:00 AM → today's show (preShow, instead of NoShow); ≥ 3:00 AM → unchanged. Restart App now works in that window too.
